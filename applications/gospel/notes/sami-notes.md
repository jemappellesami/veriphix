- the goal here is to use the outputs of test rounds of verification protocols as a benchmarking tools for quantum computers
- the reason is the following. Traps failure gives us the information whether or not computation has been affected by noise. Having more test rounds failure than the threshold is catastropic because it means that the noise might have affected the outcomes of computation rounds enough to corrupt the final result.
- So test ronuds failure rate gives us an information whether the machine's noise is big enough to compromise the computation. this guarantee is given by a cryptographic proof: we prove the exponentially small distance between the protocol (with a right threhsold) and the ideal resource.
- furthermore, we use no assumption on the noise other than the fact it is iid over the rounds
- furthermore, the results that verification protocol give us are actually independent of the true target computation, since verification is blind by default. Indeed, all computations that share the same underlying graph would have been affected the same way. This means that the traps failure rate is valid for all the computations sharing the same circuit dimension. This is a critical point, very interesting to observe. If we translate the traps failure rate into a measure of feasbility, this becomes a measure of feasability of quantum computations for a given circuit dimension. Not a given circuit, not on random circuits, but it gives this: for a fixed noise on the machine, we know how well the machine performs for all computations of the same size. We measure real utility here, not application-based stuff.
- Now, we start examining the question of actual feasability.
